# Сценарій запису відео для клієнта

4 окремі ролики, без голосу — екранні підписи там, де треба пояснити.
Рекомендована довжина: 4–7 хв кожен. Записувати на тестовій копії форми, не на живій.

**Перед записом:**
- Створити тестову форму-дубль (щоб можна було ламати).
- Приховати зайві плагіни/повідомлення в адмінці.
- Розмір вікна ~1440px, зум браузера 100–110% (щоб текст читався у відео).
- Відкрити фронтенд форми в сусідній вкладці — перемикатись для демонстрації результату.

---

## Відео 1. Adding a state (повний прохід)

Мета: показати, що штат — це не окрема сутність, а просто ланцюжок питань + один пункт у списку вибору штату.

1. **RYV Forms → відкрити форму.** Показати білдер: ліворуч список нод з фільтром, праворуч редактор.
2. **Показати ноду `select_state`.** Підкреслити: це звичайне питання типу Radio, просто з Display as = Dropdown і увімкненим Searchable. Її опції — і є список штатів.
3. **Створити перше питання нового штату.** Add Node → задати:
   - Node ID: `newstate__felony_conviction` (пояснити конвенцію `{штат}__{питання}`)
   - Type: Radio
   - Title: текст питання
   - Group: назва штату — це керує, у який блок ноду складе список ліворуч
   - Options: Yes / No, поки без Next question
4. **Створити результат.** Ще одна нода:
   - Node ID: `newstate__can_vote`
   - Type: Markup
   - Content: текст результату в редакторі
   - Next question: `— End —` (пояснити: це кінець гілки)
5. **Зв'язати.** Повернутись у питання, в кожної опції вибрати Next question зі списку.
6. **Додати штат у список вибору.** Відкрити `select_state` → Add option → Label «New State», Value `new_state`, Next question = `newstate__felony_conviction`.
7. **Save.** Перейти на фронтенд, вибрати новий штат, пройти обидві відповіді.

**Екранний підпис у кінці:** порядок завжди такий — спочатку створити всі питання й результати, потім зв'язати їх, і останнім кроком додати штат у `select_state`.

## Відео 2. Що можна і чого не можна редагувати

Мета: перелік безпечних і небезпечних полів. Це найважливіше відео — знімати повільно.

**Безпечно редагувати (показати по одному, з результатом на фронтенді):**
- **Title** — текст питання, працюють інлайн-теги `<em>`, `<strong>`
- **Description** — підказка під заголовком
- **Tooltip (Help Text)** — іконка «?» біля заголовка
- **Content** у Markup-нодах — вміст результату, звичайний редактор
- **Label** опції — те, що бачить відвідувач
- **Group** — лише угрупування в списку білдера, на фронтенд не впливає
- **Placeholder** у дропдауні

**Обережно — змінює логіку:**
- **Next question** — це і є маршрут. Показати, як зміна одразу веде відвідувача в інше місце.
- **Value** опції — попередити: це технічне значення, воно потрапляє в логи відповідей. Міняти без потреби не варто, старі записи в Activity Log не оновляться.
- **Type** — зміна типу може обнулити налаштування (наприклад, з Radio на Markup — зникнуть опції).

**Не чіпати без потреби:**
- **Node ID** — показати, що перейменування автоматично оновлює всі посилання, тому воно безпечне технічно, але ламає зовнішні посилання/нотатки. Правило: не перейменовувати без причини.
- **CSS Class** — службові класи типу `text-restrict-height`, `message--path-end` керують виглядом, видаляти не можна.
- **Hidden** — пояснити: вмикається автоматично при імпорті, коли правило було неоднозначним. Вимикати лише після перевірки оригіналу.
- **Reference Content Nodes** — це посилання на блок довідкового тексту, який показується під питанням. Видалення прибере той текст з екрана.
- **Unsupported / needs review** — тип, який імпорт не зміг розпізнати. Не видаляти, повідомити нам.

**Екранний підпис:** видалення ноди, на яку хтось посилається, лишає розрив у ланцюжку. Перед видаленням — перевірити фільтром, чи ніхто на неї не веде.

## Відео 3. Налаштування логіки штату

Мета: показати, як довести кожну відповідь до правильного результату.

1. **Намалювати схему на екрані** (проста картинка або в білдері) — питання → відповіді → результати.
2. **Фільтр у списку нод** — ввести префікс штату, показати, що видно весь ланцюжок цього штату.
3. **Пройтись по кожній ноді** й показати Routing:
   - Radio/Checkbox → Next question задається **в кожної опції окремо**
   - Markup/Text → одне поле Next question на всю ноду
4. **Показати `— End —`** — так позначається фінальний екран.
5. **Показати, що список Next question містить лише існуючі ноди** — навести на неіснуючу ноду неможливо.
6. **Перевірка:** пройти форму на фронтенді по кожній гілці. Підкреслити: перевіряти треба всі відповіді, не одну.
7. **Типова помилка:** опція без Next question — показати, що відбувається (форма зупиняється), і як виправити.

## Відео 4. Редагування штату при зміні правил

**Сценарій А — додалось нове правило (нове питання посередині):**
1. Створити нову ноду з питанням.
2. Знайти те місце, куди вона має вклинитись.
3. Перенаправити Next question попередньої ноди на нову.
4. У новій ноді розставити Next question на ті результати, куди раніше вів попередній крок.
5. Save → перевірити гілку на фронтенді.

**Сценарій Б — правило прибрали:**
1. Знайти ноду, яку треба прибрати.
2. **Спочатку** перенаправити все, що на неї вело, на наступний крок. Показати, як знайти ці посилання через фільтр.
3. Тільки після цього видаляти ноду.
4. Save → перевірити.

**Сценарій В — змінився текст результату:**
- Відкрити Markup-ноду → відредагувати Content → Save. Логіки не торкаємось.

**Наприкінці:** показати **Activity Log** — хто і коли зберігав, які ноди додано/змінено/видалено. Пояснити, що це спосіб побачити, що саме зламалось, якщо щось пішло не так.

## Загальні поради на всі 4 ролики

- Кожну зміну доводити до фронтенду — клієнт має бачити причину й наслідок.
- Робити паузу 2–3 секунди перед кожним кліком, щоб відео можна було ставити на паузу.
- Наприкінці кожного ролика — один екран із підсумком у 3–4 пункти.
- Згадати сторінку **RYV Forms → Help**, де ті самі інструкції текстом.
